- (direction) User goal: OpenClaw/Hermes act as always-on knowledge librarians over multiple Lumina wikis; user-driven ingest/ask via chat (Telegram etc.); wikis live at arbitrary user-chosen paths, some pre-existing (GitHub/Drive synced).
- (decision) Architecture: single librarian agent + shared global registry (Option A) over one-agent-per-wiki; registry is the single source of wiki locations.
- (decision) Registry file ~/.lumina/wikis.json, outside any agent workspace, shared by OpenClaw and Hermes; per-wiki fields: name (user-given), aliases[], path (absolute), description, packs; field name topics is banned - collides with the wiki topics/ page type.
- (decision) Resolver is deterministic code: new lumina wikis subcommand (add/remove/list/resolve/doctor) with --json output and the existing exit-code contract; resolve verifies _lumina/manifest.json exists before returning a path.
- (decision) Routing protocol lives in a SKILL.md preamble - the only context guaranteed present at invocation on both platforms; cwd-is-wiki check first so classic single-wiki use is unchanged (graceful degrade).
- (decision) No reliance on ambient cwd: every wiki operation is a one-shot cd abs-path && command; the path always comes from resolver output, never from model memory.
- (decision) In librarian mode the agent MUST read the target wiki's README.md before any operation on that wiki.
- (decision) Ambiguity rule: explicit name/alias wins; else a unique confident match by description (the choice must be stated aloud); else ask the user - never guess.
- (decision) Installer gains an AI Agents target group (openclaw, hermes): installs skills only, into each platform's documented global skills directory; post-install next-steps notice with Enter-to-acknowledge in interactive mode.
- (decision) Existing defect elevated to requirement: skills install must be non-destructive everywhere - manage only lumi-* entries it owns, never delete or overwrite foreign skills in any skills directory (global or project).
- (decision) Chat-received documents land in the target wiki's raw/tmp/ as new files (collision-safe names, never overwrite), then normal /lumi-ingest.

- (note) Attachment transport verified in both codebases.

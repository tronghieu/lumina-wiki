- (direction) Source: docs/brainstorming/brainstorm-lumina-project-docs-overlay-2026-09-26/brainstorm-intent.md (+ its .memlog.md). Mode: express distill, input is rich. Slug project-docs-overlay. Branch feat/project-docs-overlay.
- (capability) CAP-1 Separate install mode for an existing project repo, distinct from --ide and --agents; installs engine, skills, config; creates no raw/ or wiki/; overwrites no existing entry files.
- (capability) CAP-2 Configurable source scope: multiple include/exclude globs, default docs/, exclude wins, zero-match include warns.
- (capability) CAP-3 Setup skill: scans in-scope docs, proposes scope, project ontology mapped to meta-types, ID patterns, status sources, external IDs, concept vocabulary; flags frontmatter problems; writes config only after user approval; applies only user-approved frontmatter fixes.
- (capability) CAP-4 Two-tier ontology: fixed meta-ontology (meta-types + meta-relations with lint semantics); project types and relations must each map to a meta-type/meta-relation.
- (capability) CAP-5 Deterministic parse (fast path) of frontmatter, links, ID mentions, heading-based status, concept vocabulary mentions; identical output on repeat runs; not committed.
- (capability) CAP-6 Ontology-guided agent ingest: host agent extracts entities, fragments, relations per doc; every fact carries evidence quote + file:line; stored committed, one record per source doc keyed by content hash; incremental on changed docs only.
- (capability) CAP-7 Node granularity: document, fragment (ID/anchor-addressable), concept (name, aliases, mentions; no prose).
- (capability) CAP-8 Freshness: hook rebuilds parsed part and marks agent facts stale on doc hash change; queries rebuild parsed part when stale and report stale-doc count.
- (capability) CAP-9 Cross-doc lint keyed on meta-relations; reports only; runnable in CI without an agent.
- (capability) CAP-10 Ask: human asks via host agent; answer from graph cites file:line.
- (capability) CAP-11 Evidence verify: detects facts whose evidence quote no longer exists at source.
- (capability) CAP-12 Graph view: self-contained HTML with Obsidian-like graph interaction, colored by meta-type, lint/stale highlighting, detail panel with evidence and editor link.
- (constraint) Docs are the only source of truth: Lumina writes no markdown pages and never edits docs except user-approved frontmatter fixes during setup. Graph holds typed relations, pointers, evidence quotes; no prose.
- (constraint) Lumina calls no LLM API; all inference is done by the host coding agent through skills. Hooks never invoke the agent.
- (constraint) Meta-ontology is pure data in code (schemas.mjs discipline); lint and cross-wiki queries key on meta-types, never on project type names.
- (constraint) Glob syntax * and ** only via src/scripts/lib/globs.mjs; one matcher shared by scanner, hook, lint; patterns repo-relative through safePath; always-excluded .git/ node_modules/ _lumina/; default-excluded agent-tool dirs and graphify-out/.
- (constraint) Parsed graph and viewer gitignored; agent-extracted facts committed per source doc.
- (constraint) Viewer: single HTML, data inline, works from file://, canvas rendering, force-graph 2D used directly, no React, no CDN (zero-telemetry rule 10), library vendored as a static asset.
- (constraint) Classic IDE installs and AI-agent installs stay byte-identical; repo policies hold (atomicWrite, no postinstall, no native modules, devDependencies empty, cold start <300 ms with lazy imports, exit codes 0-4, no emoji, en/vi/zh doc sync).
- (decision) Project mode suspends classic wiki invariants inside project repos (reverse edges written into pages, wiki.mjs page writes, raw/ wiki/ layout, timeline/compiled zones); reuses schemas/graph/lint engines, lumi-ask, lumi-verify. Recorded in brownfield.md.
- (decision) Non-goals: code analysis, code wiki generation, doc-to-code drift; duplicate markdown or Obsidian vault export; hosted UI/server; React or 3D viewer in v1; per-file checks existing tools own; custom lint rules; Lumina-driven autonomous ingest.
- (decision) Success signal: Seli kill criterion (~10 real manager questions/lint cases, graph+lint beats agent-with-grep on most); Capigo ADR status via heading; third non-BMAD pilot (kubernetes/enhancements KEPs) mapped by setup with no code change.
- (assumption) Coach-proposed brainstorm items the user did not reject are accepted: glob semantics, external_ids, status_from, meta-type table, lint rules, viewer feature list, concept vocabulary in config.
- (question) Keep (source meta-type, target meta-type) inference for untyped related: fields? Coach recommends keep: the parsed part needs typing without an agent.
- (question) Is the fixed meta-type list complete? Answer via third pilot.
- (question) Relations that map to no meta-relation fall back to references and lose lint. Acceptable long-term?
- (question) Install flag name, and whether project mode adds a marked block to existing AGENTS.md/CLAUDE.md so host agents discover Lumina.
- (question) Can a project-mode repo register in lumi-hub?
- (question) Viewer library: vendor force-graph (size, ci-package allowlist) or hand-written canvas force layout?
- (event) Pass 1 coherence: pass. 12 capabilities with intent+success; constraints bend design; 7 non-goals; testable success signal. Fixed: open question on entry-file block now notes it would amend CAP-1; related-typing example rephrased to meta-relation direction.
- (event) Pass 2 preservation: pass. All confirmed brainstorm decisions landed. Not carried as capabilities (coach ideas, unconfirmed): separate traceability views (covered by graph view + ask), encoding doc-precedence rules such as 'ADR wins', mermaid parsing into Process steps (left to agent ingest).
- (decision) Keep meta-types. Without them either each project writes its own lint rules (users will not) or there is no lint (Lumina becomes a plain graph like graphify).
- (decision) Scope: software projects are the primary target; the design stays open to projects of similar complexity in other domains (construction, marketing, research). Software pilots come first.
- (constraint) Domain neutrality: lint attaches only to governance meta-types (Decision, Requirement/Goal, Rule) and generic relation rules (cycles, contradicts); setup-skill guidance must not assume software doc types, ID schemes, or folder names as the only frame. Other meta-types are labels for grouping, color, and cross-wiki queries.
- (note) Mapping check: 8 of 10 meta-types fit construction, marketing, and research naturally; Capability and Structure lean software.
- (decision) Pilots 1-3 stay software (Seli, Capigo, KEPs). A non-software pilot (GitLab Handbook: public markdown policies, processes, roles, decisions) follows later and is not a gate for this spec; Capability/Structure naming is revisited after it.
- (decision) Keep the (source meta-type, target meta-type) rule for typing untyped related: fields; without it every parsed related: link becomes references and parsed-part lint is nearly useless.
- (decision) Relations mapping to no meta-relation fall back to references in v1. A new meta-relation is added to Lumina only when pilots show an important relation keeps falling back; no user-defined lint.
- (decision) Project mode adds a short block between <!-- lumina:project --> markers in existing AGENTS.md/CLAUDE.md pointing to the setup skill, reusing the lumina:schema marker mechanism. CAP-1 amended: pre-existing files change only inside that marker region and .gitignore. Install flag name is left to architecture.
- (decision) lumi-hub registration of project-mode repos deferred: no real need yet; cross-wiki queries are already a librarian-mode non-goal.
- (decision) Graph view vendors force-graph as a static asset, subject to a package-size measurement and the ci-package allowlist; a hand-written force layout is rejected (matching Obsidian-like interaction is a sub-project).
- (event) Update re-validated: coherence pass (CAP-1 intent and success amended together; lumi-hub added to non-goals); preservation pass (all five resolutions landed in SPEC.md or companions). Open questions left: meta-type completeness, install flag name.
- (decision) Adopted companion: architecture spine docs/planning-artifacts/architecture/architecture-project-docs-overlay-2026-09-26/ARCHITECTURE-SPINE.md (AD-1..AD-26), final.
- (decision) Scope matcher lives in the self-contained project engine (src/project/lib/scope.mjs) with the same * and ** semantics as classic matchGlob, verified by a parity test; it does not import src/scripts/lib/globs.mjs, which is not installed in project mode. Amends source-scope.md and the source-selection constraint.
- (decision) Project config is YAML at _lumina/config/project.yaml, parsed by a vendored js-yaml.
- (constraint) Project-mode host targets in v1: Claude Code, Codex, Antigravity (user-confirmed); other IDE targets deferred.
- (event) Update re-validated: coherence pass; preservation pass (spine decisions reflected where they amend spec wording).

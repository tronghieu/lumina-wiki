- (direction) Source: in-chat design session 2026-09-27, branch feat/project-parallel-ingest (PR #68). SPEC.md was hand-authored first; this memlog backfills it plus the session's decisions. Slug project-parallel-ingest.
- (direction) User 2026-09-27: on a project with hundreds of docs, spawning many ingest agents must not break the graph; setup stops at config and should lead into ingest; parallel ingest should be the default, clustered by ontology type.
- (decision) Engine already safe for concurrent writers: per-doc fact files, facts-write holds _lumina/_state/lock and re-checks sourceHash under it, graph rebuilt from docs+facts on every read (AD-12), resolver never reads other fact files, so write order cannot change the graph. Only skill orchestration is missing.
- (decision) Partition in the skill, no engine helper (graphify pattern). A missed doc stays non-fresh and a sweep catches it; a doc written twice ends with the last valid set. Only engine change is status reporting type/metaType.
- (decision) Viewer stays one self-contained inlined file (AD-16); splitting it into a fixed HTML shell plus data file is a non-goal. view.html is gitignored because it inlines the data, so it is derived output.
- (capability) CAP-1 Doc type in status: status reports each doc's project type (omitted when untyped) and metaType (Document when untyped) next to path, hash, state; existing fields and summary unchanged. Success: fixture with a typed and an untyped doc.
- (capability) CAP-2 Parallel ingest by default: over 20 candidates and a host subagent tool, lumi-project-ingest orchestrates clusters and merges reports; at or below 20, or with no subagent tool, sequential as before.
- (capability) CAP-3 Partition rule: sort by (type ?? metaType, path); contiguous near-equal clusters; orchestrator states N, K and per-cluster counts summing to N before dispatch.
- (capability) CAP-4 Sweep for missed docs: after all subagents return, status; candidates not fresh and not reported skipped/stopped are re-dispatched once (orchestrator itself when 5 or fewer); still missing is reported, not retried; stopped clusters' docs are named for a re-run, not swept.
- (capability) CAP-5 One approval, isolated failures: >20 gate asked once by the orchestrator with the plan; subagents never ask; a batch-stopping exit 3 stops only its own cluster.
- (capability) CAP-6 Setup hands off to ingest: after config written and DoD passes, setup offers to run ingest; yes starts it and counts as the >20 approval; setup never runs facts-write.
- (capability) CAP-7 Ingest regenerates the view: after the final status, ingest runs view once and reports its url; a view failure does not change the ingest outcome.
- (constraint) Only engine change is CAP-1; facts-write, the lock, and the fact-file format unchanged. AD-16 and AD-12 unchanged.
- (constraint) Subagent brief carries paths with status hashes and the gate-approved note; only the orchestrator runs the final status, the sweep, and view. Host-neutral wording (Claude Code, Codex, Antigravity). All project-context.md policies hold, including en/vi/zh doc sync.
- (decision) Initial partition K = min(8, max(2, ceil(N/25))); max(2) so a batch of 21-25 still splits in two.
- (event) Implemented in 348740d: status metaType/type, orchestrator mode O1-O5 plus cluster subagent section, setup step 9 handoff, ingest step 6 view, 20-writer concurrency test, user guides en/vi/zh, CHANGELOG.
- (event) Code review 2026-09-27 (blind, edge-case, verification-gap, acceptance layers): 1 decision, 10 patches, 2 deferred, 9 rejected. Fixes in ce41858.
- (decision) Review D1, user chose to follow graphify: clusters of at most 25 docs, K = max(2, ceil(N/25)), no agent cap, all clusters dispatched in one message, host queues beyond its own parallel limit. Supersedes the min(8,...) rule; the 8 cap put 125+ docs on one subagent at N=1000, recreating the context overflow this feature exists to fix.
- (decision) CAP-4 amended: more than 5 misses are split by the CAP-3 rule and dispatched, not sent as one unbounded cluster.
- (decision) CAP-2 success and the success signal amended: 'build byte-identical to a sequential ingest of the same fact files' is tautological and two LLM runs never produce equal builds; replaced by every candidate in exactly one brief and every candidate ending fresh or named in the report.
- (decision) CAP-6 amended: setup reports N = never-ingested + changed + stale (fresh docs are never re-ingested), skips the offer at N = 0, passes 'ingest all'; a host that cannot invoke another skill gets the command '/lumi-project-ingest ingest all' instead.
- (decision) CAP-7 amended: view runs only when at least one doc was committed.
- (decision) Constraint amended: the brief points the subagent at the ingest SKILL.md for the per-doc procedure and output line format rather than copying them.
- (decision) Ingest step 1 branches to orchestrator mode before its own >20 question so the gate is asked once, at O2; a 'no' or smaller subset re-enters step 1's rule. O4 deduplicates uncaptured relations.
- (assumption) Lock contention negligible at 20 concurrent writers (one read + hash + atomic write under lock); the 20-writer stress test confirms it.
- (assumption) Cross-cluster scope-label synonyms are rare and caught by lumi-project-verify/check, which the report suggests in a fresh context.
- (assumption) Ingest allowed-tools stays [Bash, Read]: copied verbatim by the installer, pre-approval not restriction on Claude Code, ignored elsewhere; the Seli run confirms the subagent tool is usable without a prompt.
- (question) End-to-end success checks of CAP-2/4/5/6 (Seli 234-doc run, forced lock-timeout cluster, sweep with a missing doc, one-approval handoff, wall-clock comparison) need a manual pilot with real subagents; deferred to docs/implementation-artifacts/deferred-work.md.
- (decision) CAP-6 success amended: 'no second command' holds only on a host that can invoke another skill. CAP-1 success tightened: untyped doc omits type (shipped behavior), not null.

Wiki View Architecture

A local, read-only viewer for a Lumina wiki. The agent writes the wiki. You read it here, with the typed graph beside the page.

The graph is the main surface, on the left. The tree is on the right. The reader appears between them when a page is open. One page is open at a time, and all three panes follow it.

Three layers, one direction

Each layer knows only the one beneath it. Nothing writes to the wiki. Nothing is cached, so a browser reload always shows what is on disk.

What happens when you ask for the viewer

The lumi-view skill runs one command. The server finds a port, prints its address once, and stays up for as long as its starter keeps it.

sequenceDiagram
  participant H as Agent host or you
  participant V as view.mjs
  participant B as Browser
  H->>V: node _lumina/viewer/view.mjs
  V->>V: find the wiki, probe 20 ports, listen
  V-->>H: one JSON line with the address
  B->>V: GET /
  B->>V: GET /api/wiki
  V-->>B: schema, nodes, edges, communities
  B->>V: GET /api/lint
  B->>V: GET /api/page for the open page
  V-->>B: frontmatter, body, resolved links
  H->>V: stop
  V-->>H: port released, nothing left on disk
  • The port is derived from the wiki's path, so the address stays the same between starts.
  • A second start finds the running server by asking /api/health and reports its address. No state file is involved.
  • If a sandbox refuses the port, the command fails with a named reason, and the skill gives you the same command to run in a terminal.

Rules that keep the parts in step

Five units are built separately. These are the decisions none of them may make alone.

AD-4

One name per page

A page's id is its path under wiki/ without .md. The graph, the tree, and every link use that same string.

AD-5

One resolver

Links and edge endpoints are resolved by lint's resolveWikilinkTarget, on the server. The client only looks ids up.

AD-6

Edges cleaned once

A relation stored in both directions becomes one arrow. A symmetric relation becomes one line. Output is sorted, so clusters come out the same everywhere.

AD-7

A fixed contract

Seven routes, with every key and value pinned. One fixture workspace feeds the tests on both sides.

AD-21

Three functions

The read model exports readWiki, readPage, and readLint. The server serializes what they return and adds nothing.

AD-15

One owner per fact

The open page lives in the URL hash and nowhere else. Back and reload work without extra code.

AD-3

Reuse by export

Engine code is imported, never copied. The one exception, community detection, has a test that compares it with the original.

AD-22

One owner per file

Every file belongs to exactly one unit, shared files included.

Why it is safe to leave running

Wiki pages are written from sources the agent ingested, so their content is treated as untrusted. A local server is also reachable by other programs and by web pages in your browser.

GuardStops
Listens on 127.0.0.1 onlyAccess from the network

Request text is never used as a pathReading files outside the wiki

Strict content security policyAnything the guards above missed

How the client reaches users

The client is the only built file in the package. It is built by the maintainer, committed to git, and checked on every pull request.

flowchart LR
  ui[React source] --> build[build-viewer script]
  build --> js[viewer.js in git]
  js --> ci[CI on Linux, macOS, Windows]
  ci -->|rebuild and compare| ok{Same bytes?}
  ok -->|yes| pub[Publish to npm]
  ok -->|no| stop[Release blocked]
  pub --> inst[Installer copies an explicit file list]
  • No bundler runs on a user's machine. Starting the viewer needs only Node.
  • The installer stops if a listed file is missing, so a broken package cannot install quietly.
  • The build fails if a bundled library is missing from the license notices.

Still checked by hand

Ctrl-C in a Windows terminal, and pane behavior in a real browser. The project allows no browser test framework, so these stay on a manual list before each release.

Left out on purpose

  • Editing from the viewer. The agent edits the wiki.
  • A background daemon, or a server that outlives its starter.
  • Pushing changes to the browser. You reload.
  • A cache. It comes back only if a real wiki takes over a second to load.
  • Math, syntax highlighting, and embedded images in the reader.
  • A lumina view command, and opening the browser for you. Both wait until someone asks.

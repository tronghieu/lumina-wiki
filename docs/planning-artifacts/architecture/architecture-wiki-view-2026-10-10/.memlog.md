- (decision) Paradigm: read-only layered web app. Pure read model, thin HTTP adapter, single-page client; dependencies point inward. Alternatives weighed: server-rendered HTML (no React value, user chose React) and a static export (rejected by the user). Binds all units; prevents the UI reading files or the server rendering views.
- (decision) Viewer is its own tree src/viewer -> _lumina/viewer, copied by an explicit list that exits 3 on a missing file, not through copyScripts. Sibling-relative imports to ../scripts work in the repo and when installed. Prevents silent missing assets and files leaking into the scripts walk.
- (decision) Engine reuse is by export from lint.mjs, schemas.mjs and lib/edges.mjs; a needed unexported symbol (WIKILINK_RE) gets exported at its home rather than copied; wiki.mjs is not imported. The viewer entry file is view.mjs so no argv-suffix guard fires. Prevents a second resolver, a second frontmatter parser, a second type list.
- (decision) Community detection is the one copy: the project tree is not installed in classic, so src/viewer/lib/communities.mjs duplicates detectCommunities and a parity test compares both on a shared fixture. Prevents silent drift between the two copies.
- (decision) Node id is the wiki-relative path without .md (lint knownSlugs entry); url:<href> for external targets; missing:<target> for endpoints that do not resolve. Only the read model mints ids; one resolver for links and endpoints; the UI only looks ids up. Prevents graph nodes, tree rows and reader links disagreeing on identity.
- (decision) Edge normalization happens once in the read model: symmetric types undirected and stored once; of two stored edges that are each other reverse, keep the one whose type names the other as reverse, tie broken by EDGE_TYPES order; citations become cites edges tagged with their source file. Nodes and edges are emitted sorted. Prevents double arrows and non-deterministic communities.
- (decision) HTTP contract: /, /assets/viewer.js, /assets/viewer.css, /api/health, /api/wiki, /api/page?id=, /api/lint. Bodies are fetched per page; lint is its own route so a slow or failing lint never blocks the graph. Errors use {error,message}. Prevents UI and server inventing shapes independently.
- (decision) Request input never becomes a filesystem path: page ids are looked up in the id-to-file map built from the walk, assets in a fixed map. This is stricter than the spec wording "through safePath" and replaces it. Prevents traversal by construction.
- (decision) Process contract: foreground; exactly one JSON line on stdout {ok,url,port,reused}; exit 2 for no workspace or a refused bind, 3 for no free port or an internal error; no state file, no timer. Port = 28000 + hash(realpath) mod 1000, probing 20 ports, asking /api/health first to find a running server for the same root. Prevents two servers per workspace without any state on disk.
- (decision) Rendering: markdown-it with html off, linkify off, image rule off; HTML comments stripped before rendering (with html off they would print as text); wikilinks rendered from the links map the server returns; output injected at one place only. Chosen over marked+DOMPurify (needs a DOM, not testable under node --test) and react-markdown (larger dependency tree). Prevents script injection from ingested content and external image requests.
- (decision) UI state: the open page lives only in the URL hash; one reducer holds view settings; only the graph pane touches force-graph; ui/lib modules import no React and no DOM. Prevents three panes holding three copies of the selection, and keeps logic testable.
- (decision) Build and guard: scripts/build-viewer.mjs with fixed esbuild options writes src/viewer/app/viewer.js; CSS is authored, not bundled; names are fixed, never hashed. ci:viewer-bundle rebuilds and git-diffs on all three CI operating systems and in publish before ci:package. The build fails when a bundled package is missing from the third-party notices.
- (decision) Tests are the cross-platform proof: test:viewer runs on ubuntu, macos and windows in CI, including server start, Host rejection, reuse and stop. This closes the two risks the spec carried as untested (Windows server, Linux bundle bytes) once CI is green.

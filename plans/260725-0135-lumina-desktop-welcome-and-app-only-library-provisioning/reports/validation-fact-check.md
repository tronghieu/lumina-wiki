# Plan Validation: Phase 1–2 Fact Check

Date: 2026-07-25  
Scope: edited `plan.md` and all five phase files were read; the concrete
fact-check below concentrates on Phase 1 and Phase 2 as requested.

Method: repository reads and file/symbol searches only. No build, lint, type
check, or test command was run. Official Go and Microsoft primary documentation
already cited by the plan research was rechecked.

Status meanings:

- **PASS** — the current source or primary documentation supports the claim, or
  the planned `create`/`modify` action correctly names a verified current gap.
- **CONDITIONAL** — direction is supportable, but the stated contract/command
  needs the correction shown before it is executable evidence.
- **FAIL** — the plan contains a factual or interface contradiction that cannot
  produce the stated behavior as written.

## Corrections required before execution

1. Change Phase 2’s constructor from raw `Payload` to `Bundle` or a narrow
   verified materializer interface.
2. Replace the trusted-attach return type with an actual `PreparedAttach`
   transaction contract; the current signature cannot support `Commit/Abort`.
3. Replace cross-package `os.FileInfo` proof with a versioned proof that can
   carry Windows volume + 128-bit `FileIdInfo` evidence.
4. Make the lint-ID authority explicit rather than “modify if needed.”
5. Treat the `GOOS=windows ... -exec=true` command as compile-only evidence.
6. Implement a branch-aware Go patch gate so vulnerable 1.26.1 cannot satisfy a
   naïve `>=1.25.12` check.
